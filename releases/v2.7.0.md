## v2.7.0

本次修掉三个计时问题（其中两个「虚高 / 不归零」是同一类根因的反复发作），并补上系统亮屏时长对照、时间设置滚轮化与一批视觉修正。

### 修复：用眼时长统计虚高

报告页的用眼时长与系统「屏幕使用时间」对不上，**虚高**。用户实测：息屏前 3 小时 17 分，息屏一小时后亮屏显示 4 小时 19 分，多算 62 分钟；另有「系统亮屏 3 分钟、自统计 33 分钟」。

根因是 `screenOnAt` 这个**进程内推断值**被无条件采信。它一旦失真（进程在息屏期间被杀、广播被系统丢弃、厂商省电策略拦截），`当前时刻 - screenOnAt` 就会把**整段息屏时间当成连续用眼**结算入统计。

修复方式：所有累计入口把**真实屏幕状态**交叉传进来（`accumulatedAt(state, at, screenActuallyOn)`），屏幕实际熄灭时一律按「未在累计」处理，拒绝把陈旧亮屏时刻的墙钟差计入。同时给累计段引入**代际序号**（`accumGeneration` / `recordedGeneration`）：只要开启新一段，序号 +1、结算水位线同步归零，`recordWorkSession` 只在序号一致时才认旧基准——此前靠 `recordedAccumMs > workAccumMs` 事后猜「是不是换了新段」，在 `resync`、`onScreenOn` 短暂息屏续算等只归零累计却漏归零水位线的路径上会失效。

### 修复：息屏后亮屏不重置计时（`offAt` 从未落盘）

「熄屏一段时间后亮屏，计时从 0 重新开始」这条路径失效，且**时好时坏**。

两个独立缺陷叠加：

1. `onScreenOff` 最常走的 `branch=NORMAL` 分支把 `recordWorkSession(...)` 的**返回值直接丢弃**，而该函数已改为纯状态推进（只 `return state.copy(...)`，内部不再落盘）。于是 `offAt = t` 算得对却**从未写入磁盘**，磁盘恒为 `-1` → 亮屏时 `leftLong = offAt > 0 && ...` 恒假 → 判不出「离开过」。
   日志铁证：`10:29:38 [REC-WORK] offAt=1791944978132`，4 分 34 秒后 `10:34:12 [SCREEN-ON] offAt=-1`。
   修法：显式落盘，不再依赖被调用方的副作用（`TimerStore.save(context, settled.copy(offAt = t))`）。

2. `ACTION_USER_PRESENT` **只在「锁屏 → 解锁」时才发**。曾一度把 `ACTION_SCREEN_ON` 改成「只同步久坐提醒、不调 `onScreenOn`」，以「避免同一轮亮屏被处理两次」——**这个理由是错的**。若息屏前本就没有锁屏（看视频 / 读长文时自动息屏），亮屏时系统只发 `SCREEN_ON`，于是归零路径**一次都不执行**；锁屏后再解锁才生效，表现就是间歇性失效。
   修法：还原为两个 action 都触发 `onScreenOn`，并把规则抽成 `startsScreenOnSession(action)` 纯函数由单测锁住。幂等本就不需要靠掐掉广播源：[`onScreenOn`] 入口就用 `consumeScreenOnEdge()` **读后清零**边沿标记，第二次进来 `cameFromScreenOff` 必为假，归零判定自然不成立。

### 修复：次日首次亮屏误弹「超时 500+ 分钟」

跨天时 `screenOnAt` 被无条件改写为有效值，清晨采信了**跨夜**的陈旧时间戳，于是 `elapsed >= workMs` 恒真、每次亮屏都触发。

修法：「本段累计起点」只有在**本段仍在累计中**（字段有效）**且屏幕此刻真的亮着**时才可延续，否则必须以当前时刻重新起算，绝不把陈旧跨度接进新段。`elapsed` 改为基于**刚落盘的状态**计算，不再重新读盘（重读会拿到与判据不同的快照）。

另外两处同源问题一并修掉：**切后台回来从零重算**（兜底判据 `workAccumMs <= 0L` 与 `newSegment` 形成自维持死循环，实测段序号一路疯涨 79 → 84 → 85）、**亮屏误弹超时**（`ACTION_SCREEN_ON` 与 `ACTION_USER_PRESENT` 是两次独立广播，原实现把 `offAt` 抹成 -1 后第二次进入 `leftLong` 恒假并重排超时闹钟）。

### 新增：系统亮屏时长对照

新增 `data/ScreenTimeStore.kt`，用 `UsageStatsManager` 查 `SCREEN_INTERACTIVE` / `SCREEN_NON_INTERACTIVE` 事件逐对累加今日亮屏时长，在报告页与自统计**并排对照**，含四分支判读文案（自统计偏多 / 两者基本一致 / 差的是亮屏但没在用眼的时间 / 亮屏比用眼多）。

**刻意不替换用眼时长**——亮屏 ≠ 用眼，两者是不同的量，并排展示才能看出统计是否可信。申请 `PACKAGE_USAGE_STATS` 权限，无权限时该栏自动隐藏并提供跳转入口。

### 新增：时间设置改滚轮

分钟类设置由步进器改为滚轮（`LazyColumn` + `rememberSnapFlingBehavior`，按距视口几何中心偏移做缩放与透明度）：

- **停稳后高亮中间格**，底部「取消 / 确定」两按钮，点确定才写入（滚动只改 draft）；
- 每日用眼目标改**双栏**（左小时 0..12 + 右分钟 0..59，1 分钟步进），允许 0 小时，不联动，下限仍 clamp 到 10 分钟；
- 字号 18sp→20sp、行高 44dp→48dp、视口 220dp→240dp、单位标签 14sp→15sp。

踩坑记录：最初按 `firstVisibleItemIndex` 取选中项，吸附收尾会多翻一格 → 改为按「项中心距视口中心最近」取值，且只在 `isScrollInProgress` 转 false 时读一次。

### 视觉与交互修正

- **`EyeIcons` 扩充**：新增 `CheckCircle` / `AlertCircle`（矢量勾与叹号）。起因是「提醒可靠性自检」页的 ✅ / ⚠️ emoji 与文字基线不齐、行高被撑开换行；同源问题此前也出在底部导航（已换矢量图标）。同步替换报告页「今日用眼小结」与「护眼小知识」标题的 emoji。**科普提示、通知、休息页的 emoji 按用户要求保留**（那是内容的一部分，不是功能标记）。
- **免打扰卡片**改 Row + 左侧竖条，替代原 emoji 提示；**首次引导弹窗**标题改矢量图标 + 文字。
- **首页三页标题改为居左**，删除两处副标题。
- **导航栏高亮改为即时**：`goTo` 先切 `currentTab` 再动画滚页，不再等 `settledPage` 回调（原来有可见延迟）。
- **休息页两个按钮**改绿色实心填充、各占一半宽度（原一宽一窄）。
- **统计口径修正**：`addWorkSession` 增加 `streakSeconds` 参数。原来每次增量结算都被当成一段独立的「连续用眼」，真连续 40 分钟会被拆成多段显示成 2 分钟。

### 清理

删除临时诊断基建（`data/DiagLog.kt`、`EyeTimer` 内 11 处状态日志与来源标记、`TimerStore.save()` 的写盘追踪、设置页「计时诊断日志」区块），以及仓库根 `AGENTS.md`。诊断代码在排查上述问题时很有用，但每次写盘多一次 prefs 读与栈回溯，问题定位后按计划移除。

### 验证

单元测试 **79 / 79 通过，0 失败**（新增 `ScreenTruthTest`、`GenerationDedupTest`、`ScreenEdgeDispatchTest`，其中 `ScreenEdgeDispatchTest` 专门锁住「`SCREEN_ON` 与 `USER_PRESENT` 都必须触发亮屏会话」，防止再有人把 `SCREEN_ON` 摘掉）。

真机验收：用眼时长统计、息屏后亮屏重置、**跨天亮屏重置**均通过。

### 教训

这轮排查走了弯路：怀疑回归时先去反编译 APK 逐字节对比 dex，解析器反复出错（`field_ids` 与 `method_ids` 偏移写重叠、字符串长度前缀当成首字符、`class_data_item` 用绝对索引而非增量编码），花了十几轮，而真凶用一条 `git show HEAD:<文件>` 对 diff 就能看出来。

**怀疑回归时，第一件事应该是拿稳定版源码直接对 diff。**

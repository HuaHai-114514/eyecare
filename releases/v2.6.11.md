## 修复：页面切换动画的掉帧卡顿 + 全项目动效复审

**现象**
底部导航在板块之间切换时掉帧卡顿，**尤其是冷启动后的第一次切换**；之后的切换正常。

**根因（分两层，第二层是关键）**

1. **页面切换的实现方式**：原本用 `AnimatedContent` + 位移。它的问题不在「位移」本身，而在于切换时会把**新旧两页同时挂载**，两页各自跑完整的 measure / layout / draw；位移只是让这件事**每帧都可见**（连静止的旧页也要重排）。
2. **第一次切换的额外成本**：真机实测（App 内嵌帧探针逐帧记录）显示——
   - 第一次切页：50 帧里**掉 12 帧**，最差一帧 **50.0ms**
   - 紧接着第二次切同一页：82 帧，**掉 0 帧**，最差一帧 **16.7ms**（正好一个刷新周期）

   同一份代码、同一台手机，第二次干净得一帧不掉 —— 说明**动画代码本身没有问题**，多出来的是这条路径**第一次被执行时的一次性开销**（类加载 + 字节码验证 + 首次 JIT）。debug 包体 28.4MB dex 且不做优化，这笔开销尤其明显。

**方案**

1. **改用 `HorizontalPager` + 弹簧**（核心）
   - Pager 是一块横贯三页的连续画布，每帧只做一次布局，三页位移全部走各自的 `graphicsLayer.translationX`（合成层），**不触发 measure / layout / draw**。
   - 这正面回应了动效性能准则里的「只动 transform / opacity」。
   - 附带拿到 Apple《Designing Fluid Interfaces》强调的几件事：跟手 1:1、可打断、松手时速度交接、边界阻尼。
   - 落位用 `spring(dampingRatio = Spring.DampingRatioNoBouncy, stiffness = Spring.StiffnessMediumLow)`：**临界阻尼不弹跳**是 Apple 的默认约定，回弹只留给用户甩出来的手势。
   - Material3 药丸 indicator 保留，跟随 `settledPage` 同步（`snapshotFlow`）。
2. **`beyondViewportPageCount` 1 → 2**：该参数决定当前页两侧各有多少页被**提前测量**，而首次测量 = 首次组合整棵子树。取 1 时冷启动停在计时页，距离 2 的设置页不会被组合，第一次切过去要现做「组合 750 行 + 首次 measure + 首次 draw」。
3. **手写 `app/src/main/baseline-prof.txt`**（30 条）：覆盖冷启动与首次切换热点（MainActivity 生命周期、`EyeCareApp`/`TimerTab`/`ReportTab`、`EyeCareViewModel` 的 `init`/`startTicking`/`clockTick`/`syncFromStore` 两个重载、`EyeTimer` 的 `syncScreenState`/`resync`/`isScreenOn`、`TimerStore`/`SettingsStore`/`StatsStore` 热路径、`ThemeKt`/`MotionKt` 初始化）。**仅 release 生效**（已验证 debug 包内无 `baseline.prof`，AGP 只给 release 打），release 内为 `assets/dexopt/baseline.prof`，安装时即 AOT 编译。
4. **降低每秒常驻开销**（与「第一次卡」无关，但稳定吃主线程时间片）
   - `EyeCareViewModel.clockTick`：一次 tick 只读一次盘（原为 `load → save → load → SettingsStore.load`），且**只在真正跨天时落盘**（原为每秒无条件 `save`）。
   - `StatsStore` 新增只读视图 `readAll` / `readAllToday`：原 `loadAll` 命中缓存仍要 `toMutableMap()` 复制整张表（最多 90 天），而读一个「今日用眼秒数」也走这条路，每秒 7 次。
   - `ReportTab` 缓存键由**秒级**改为**分钟级**（`todayWorkSeconds / 60`）：该页所有时长本来就以分钟展示，秒级变化看不见，却每秒作废一次 `remember`，连带重跑 `dailySeries` + `achievementRate` + `workTrendPercent` 三次全表计算。

**顺带完成的动效复审（11 项）**

| 位置 | 改动 | 依据 |
| --- | --- | --- |
| `ui/RestScreen.kt` 倒计时秒数 | 删除每秒重放的 fade + scale | 1 次/秒属「100+/天 → 永不动画」 |
| `ui/SettingsTab.kt` 落盘反馈 | 加 600ms 静默窗口，长按连点只播一条 Snackbar | 原为 ~11Hz 反复重播入场动画 |
| `ui/components/DailyBarChart.kt` | 删除柱高 520ms 生长动画 | 报告页是用户要读的数字 |
| `ui/Cards.kt` 轮播跟手 | `Modifier.offset{}` → `graphicsLayer{ translationX }` | 只动 transform，不触发布局 |
| `ui/Cards.kt` 松手回弹 | 位移阈值 → **速度阈值**（300dp 换算 px/s）+ `spring(0.82)` | 动量去留由速度决定，不由位移 |
| `ui/Cards.kt` 拖拽期 | 每个 pointer 事件 `scope.launch` → 纯 `mutableFloatStateOf` 写入 | 拖拽期不该起协程 |
| `ui/Cards.kt` 页点 | 动画 `width` 6→16dp → 固定 16dp + `scaleX` | 动 width 会触发布局 |
| `ui/Cards.kt` 翻页 | 拖拽触发时只做淡入淡出 | 两条同轴位移同时播放会抖 |
| `ui/SettingsTab.kt` 步进器 | 补按压 `scale 0.94` / `PRESS_MS`，加 `Role.Button` 与语义动作 | 反馈 + 无障碍 |
| `notify/RestOverlayService.kt` | 入场补 `DecelerateInterpolator`；退出按场景分 140/220ms | 默认 AccelerateDecelerate 起手慢 |
| 全项目 | 裸 `tween(...)` → 统一走 `Motion.kt` token | 集中管理时长与曲线 |

**刻意不改**（标准判定为合理）：进度环 300ms tween（State indication）；休息页整页入场 alpha + scale(0.96→1)（只把时长收到 `MODAL_MS`）；免打扰卡淡入（频率低）；日/周/月档位切换**不加过渡**（用户要立刻看到数字）。

**验证**
- 单元测试 **46 / 46 通过**（新增 `TickerCostTest` 3 个用例，静态锁住「每秒 tick 的读写预算」；已做**变异测试**确认非空测试——故意把「无条件落盘」改回去，该用例确实失败）。
- 真机实测对比（同一台骁龙 8 Gen 3）：

| 构建 | 第一次切页 | 第二次切页 |
| --- | --- | --- |
| debug | 50 帧 / **掉 12 帧** / 最差 50.0ms | 82 帧 / 掉 0 / 16.7ms |
| release（含 baseline profile） | 87 帧 / **掉 0 帧** / 最差 8.3ms | — |

release 包第一次切换即**一帧不掉**（8.3ms = 一个 120Hz 刷新周期），确认原现象为 debug 构建固有的一次性类加载成本。**用户已真机验收通过。**
